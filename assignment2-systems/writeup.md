LayerNorm 为何被特殊对待 / BF16 是否不同
  
  LayerNorm 需要计算 var = E[x^2] - E[x]^2。FP16 的动态范围仅 ±65504，x^2 极易溢出（例如输入 300 就产生 90000 > 65504）。此外 FP16 只有 3
  位有效数字，在大序列长度上做 reduction 时累积误差严重。因此 PyTorch 将 LayerNorm 硬编码为 FP32 计算。

  BF16 的指数位与 FP32 相同（8 bit），动态范围一致，不会出现 x^2 溢出。因此在 BF16 autocast 下，LayerNorm 不需要像 FP16 那样被特殊对待——PyTorch
  的 BF16 autocast policy 也更宽松，允许更多操作直接在 BF16 下运行。不过 BF16 的尾数位少（7 bit vs FP32 的 23
  bit），在极长序列上做均值/方差归约时仍可能有微小精度损失，但不会产生 FP16 那种灾难性溢出。


 (a) 最小化峰值激活内存的最优策略
     
  策略：递归二叉 checkpointing。将 N 层从中间分成两半——前半段包在 checkpoint 中（不保存中间激活），后半段递归应用相同策略。

  def optimal_checkpoint(layers, x):
      if len(layers) == 1:
          return layers[0](x)
      mid = len(layers) // 2
      # 前半：checkpoint — 不保存中间激活
      mid_out = torch.utils.checkpoint.checkpoint(
          lambda x_in: run_forward(layers[:mid], x_in),
          x, use_reentrant=False
      )
      # 后半：递归调用自身
      return optimal_checkpoint(layers[mid:], mid_out)

  渐进分析：
  - 峰值内存 = O(log N)：递归深度为 log₂N，每层仅保存一个边界张量（一个 residual stream tensor）。单层内部其余激活均不保存。
  - 计算量 = O(N log N)：每个 block 在反向传播期间平均被重新计算 log₂N 次（每一层递归贡献一次额外 forward）。总计算量约为无 checkpointing
  的 log₂N 倍。
  
  直观对比：

  ┌─────────────────────┬────────────────────┬────────────┐
  │        策略          │      峰值内存       │    计算     │
  ├─────────────────────┼────────────────────┼────────────┤
  │ 无 checkpointing    │ O(N)               │ O(N)       │
  ├─────────────────────┼────────────────────┼────────────┤
  │ 均匀分块 (k 个一组)    │ O(N/k + k) = O(√N) │ O(2N)      │
  ├─────────────────────┼────────────────────┼────────────┤
  │ 递归二叉 (最优)       │ O(log N)           │ O(N log N) │
  └─────────────────────┴────────────────────┴────────────┘

  (b) 单层 checkpointing 下的最优策略
  
  约束：不允许嵌套 checkpoint，即每个 block 最多被一层 checkpoint 包裹。

  分析：将 N=32 层划分为大小为 k 的段，每段一个 checkpoint。峰值内存由两部分贡献：
  - 段内 k 个 block 的激活值（反向重计算时峰值）：O(k)
  - 段间边界张量 ceil(N/k) 个：O(N/k)

  单层激活值 (B=4, S=2048)：attention weights 4×32×2048²×4 ≈ 2.13 GiB/层 占主导，加上 QKV/FFN 输出每层共约 ~3.25 GiB。边界张量 (4, 2048, 
  2560) ≈ 80 MiB。

  由于每层激活值 (3.25 GiB) >> 边界张量 (80 MiB)，最优 k=1——每层单独 checkpoint：

  ┌─────────┬──────┬──────────────────────────────────┐
  │    k    │ 段数  │           峰值激活内存             │
  ├─────────┼──────┼──────────────────────────────────┤
  │ 1       │ 32   │ 1×3.25 GiB + 32×80 MiB ≈ 5.8 GiB │
  ├─────────┼──────┼──────────────────────────────────┤
  │ 2       │ 16   │ 2×3.25 GiB + 16×80 MiB ≈ 7.8 GiB │
  ├─────────┼──────┼──────────────────────────────────┤
  │ 4       │ 8    │ 4×3.25 GiB + 8×80 MiB ≈ 13.6 GiB │
  ├─────────┼──────┼──────────────────────────────────┤
  │ 32 (无) │ 1    │ 32×3.25 GiB ≈ 104 GiB (OOM)      │
  └─────────┴──────┴──────────────────────────────────┘

  结论：k=1（每层都 checkpoint）峰值内存最低，仅 ~5.8 GiB 激活 + 14 GiB 参数 + 28 GiB 优化器 ≈ 48 GiB，可在 A100 80GB 上运行。计算开销为
  2×（每层在反向时重算一次），可接受。
